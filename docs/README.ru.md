ИИ-агенты сейчас пишут большую часть тестов в своих PR, и CI зеленеет. Но тест, который проходит с фиксом, может проходить и без него, и тогда он ничего не проверяет. Receipts запускает каждый тест, который изменение добавило или поменяло, **дважды**: с изменением и с кодом, откаченным к базовой ветке. И показывает, какие тесты на самом деле доказывают изменение.

- **Детерминированно.** Никакой LLM, никаких ключей API, код не покидает машину. Вердикт — это прогон ваших же тестов.
- **Ноль зависимостей.** Нужны Node 20+ и git. Используется pytest, vitest или jest вашего проекта.
- **Там, где идёт работа:** skill для Claude Code и других агентов, GitHub Action с комментарием в PR и CLI.

## Как это работает

<p align="center">
  <img src="media/how-it-works.gif" alt="Тест на 1900 год проходит с фиксом и падает без него: PROVEN. Тест на 2020 год проходит оба раза: THEATER." width="100%">
</p>

1. **Diff.** Файлы, изменённые с момента merge base, делятся на тесты, исходники и окружение (lock-файлы, манифесты, конфиги раннеров).
2. **Изменённые тесты.** Функции pytest и блоки `it`/`test` в vitest и jest (включая вложенные `describe`, строки `parametrize` и таблицы `.each`) сопоставляются с изменёнными строками.
3. **Зелёный прогон.** Эти тесты запускаются с изменением.
4. **Красный прогон.** К базовой версии откатываются только изменённые исходники. Тесты, зависимости и конфиги остаются новыми. Те же тесты запускаются снова.
5. **Вердикт** по каждому тесту. Упавшие тесты перезапускаются, чтобы отличить нестабильные от настоящих падений.

## Вердикты

| | Вердикт | С изменением | Без изменения | Смысл |
|---|---|---|---|---|
| ✅ | **PROVEN** | проходит | падает | Тест ловит то, что чинит изменение |
| 🛡️ | **GUARD** | проходит | проходит | Охраняет соседнее поведение, а изменение доказывает другой тест. Норма |
| ⚠️ | **THEATER** | проходит | проходит | Ни один тест не доказывает изменение: все прошли бы и так |
| 🟡 | **WEAK** | проходит | падает на импорте | Вызываемого кода ещё не было. Для фичи норма, для фикса мало |
| ❌ | **BROKEN** | падает | | Изменение не проходит собственный тест |
| 🔁 | **FLAKY** | по-разному | по-разному | Нестабильный тест |
| ⏭️ | **SKIPPED** | пропущен | | Тест не запускался |

Для **рефакторинга** логика обратная: каждый тест должен проходить на обеих версиях (✅ PRESERVED), а падение на старом коде значит, что рефакторинг изменил поведение (⚠️ CHANGED). Тип изменения Receipts берёт из меток PR, заголовка `fix:` / `feat:` / `refactor:` или сообщений коммитов. Ещё он показывает **удалённые** тесты и изменения кода, пришедшие **вообще без тестов**.

## Установка

### Claude Code: плагин

```
/plugin marketplace add syntaxixr/receipts
/plugin install receipts-check@receipts
```

Плагин добавляет **skill `prove-fix`**: починив баг, Claude прогоняет Receipts на своих тестах, а если тест THEATER, переписывает тест, а не фикс, пока изменение не будет доказано. Вызвать его вручную: `/receipts-check:prove-fix`.

Ещё в плагине есть **Stop-хук**, по умолчанию выключенный: он не даёт Claude закончить ход, пока его тесты ничего не доказывают. Включите его в репозитории, которому доверяете: `git config receipts.hook true`. Подробнее в [docs/agents.md](agents.md).

### Любой агент: skill

Тот же skill работает в Claude Code, Codex, Cursor, Gemini CLI, Copilot и других агентах, которые читают `SKILL.md`. CLI уже лежит внутри.

```bash
npx skills add syntaxixr/receipts
```

**Приложения Claude** (claude.ai, Claude Desktop): скачайте `prove-fix.zip` со [страницы релиза](https://github.com/syntaxixr/receipts/releases/latest) и загрузите в *Settings → Capabilities → Skills*. Skill работает там, где выполнению кода доступен ваш репозиторий.

Нужны просто инструкции? В [docs/agents.md](agents.md) есть блок для `AGENTS.md`, который делает то же через `npx`.

### GitHub Action

```yaml
# .github/workflows/receipts.yml
name: Receipts
on: pull_request          # никогда не pull_request_target

permissions:
  contents: read
  pull-requests: write    # для комментария с отчётом

jobs:
  receipts:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
        with:
          fetch-depth: 0
          persist-credentials: false   # токен не должен достаться тестам

      # Установите проект как в обычном тестовом джобе, например:
      - uses: actions/setup-python@v7
        with: { python-version: "3.12" }
      - run: pip install -e . pytest

      - uses: syntaxixr/receipts@main  # или закрепите SHA коммита
```

Action оставляет в PR один отчёт и обновляет его, пишет сводку в job summary и по умолчанию роняет проверку на `broken,theater,changed`. Все входы и выходы описаны в [английском README](../README.md#github-action).

### Командная строка

```bash
cd ваш-проект
npx github:syntaxixr/receipts check
```

Проверяются и закоммиченные, и незакоммиченные изменения относительно `origin/HEAD`, `main` или `master` (или `--base <ref>`). После проверки все файлы возвращаются на место. Ставить ничего не нужно: сборка лежит в репозитории и не имеет зависимостей. Без npx: склонируйте этот репозиторий и запустите `node plugin/skills/prove-fix/scripts/cli.js check` из своего проекта.

Коды выхода: `0` всё доказано, `1` найден вердикт из `--fail-on`, `2` сломался сам Receipts.

## Что показали реальные репозитории

Мы прогнали Receipts по 181 реальному изменению: 81 коммит-фикс мейнтейнеров в двенадцати библиотеках (click, sqlparse, marshmallow, dateutil, dayjs…) и 100 PR с отпечатками ИИ-агентов в пяти репозиториях (Claude Agent SDK, OpenAI Agents SDK, MCP Python SDK, fastmcp, simonw/llm).

| | Доказано | Частично | Не доказано | Только WEAK |
|---|---|---|---|---|
| Фиксы мейнтейнеров | **90%** | 3% | 7% | 0 |
| PR агентов | **82%** | 5% | 2% | **10%** |

Большинство тестов делают своё дело. Слабость, которая встречается только у агентов, — WEAK: в 10% агентских PR все тесты падали на старом коде только потому, что импортировали имя, добавленное изменением, и старое поведение не проверял ни один тест. Методика, оговорки и все изменения со ссылками: [docs/study.md](study.md). Данные лежат на Hugging Face: [syntaxixr/receipts-study](https://huggingface.co/datasets/syntaxixr/receipts-study).

## Важные детали

- **Подмена на месте, с журналом.** Красный прогон подменяет файлы прямо в рабочей папке, а не в отдельном worktree, потому что editable-установки (`pip install -e .`) продолжают импортировать из исходной папки. Каждый исходный байт сначала сохраняется в `.git/receipts-backup` и потом возвращается, в том числе после Ctrl-C. После жёсткого убийства процесса всё вернёт `receipts restore`.
- **Editable-установка для Python.** Если тесты импортируют копию из site-packages, подмена до них не дойдёт. Receipts это обнаружит и пометит такие тесты SKIPPED, а не выдаст ложный THEATER.
- **Ваше окружение, ваш раннер.** Receipts запускает `pytest`, `vitest run` или `jest` напрямую, а не ваш `npm test`. Задайте то, от чего зависят тесты (`TZ`, адреса сервисов, флаги), на шаге CI или в своём shell.
- **Новые имена в начале тестового файла** не дают файлу загрузиться на старом коде, и все его тесты получаются WEAK. Импортируйте новые имена внутри тех тестов, которым они нужны.
- **Зависание — тоже провал.** Тест, который всё ещё идёт к `--timeout`, считается упавшим, поэтому фикс зависания получает PROVEN.

Ограничения этой версии: один JS-раннер на репозиторий, берётся из корневого `package.json` (для подпакета есть `working-directory`); версии `catalog:` в pnpm пока не поддерживаются; тесты находятся по шаблонам, а не полным парсером. CI гоняет тесты на Linux и Windows.

## Безопасность

Receipts запускает тесты изменения, то есть его код, ровно как тестовый джоб CI. Запускайте его там, где и так запускали бы эти тесты: в Actions через `pull_request` (**никогда** через `pull_request_target`) и с `persist-credentials: false`.

Что Receipts гарантирует сам:

- **Никаких зависимостей во время работы**, и раннеры он не скачивает: запускается только установленный в проекте pytest, vitest или jest.
- **Файлы не выходят за пределы репозитория.** Каждый путь проверяется до начала красного прогона: символические ссылки на папки (PR, который превращает `src/` в ссылку на `~/.ssh`) и подмена «файл ↔ папка» отвергаются.
- **Текст из репозитория считается враждебным.** Escape-последовательности терминала и символы смены направления текста вырезаются, код-спаны в комментарии не взломать, а секреты скрываются до публикации.
- **Комментарий в PR нельзя подменить**, а хук Claude Code включается только вручную и предупреждает агента, что имена тестов — это данные, а не инструкции.

Подробности и модель угроз: [SECURITY.md](../.github/SECURITY.md). Об уязвимости сообщайте приватно через *Security → Report a vulnerability*.

## Разработка

```bash
npm ci
pip install pytest pytest-xdist
npm test                            # сборка и тесты на настоящих проектах pytest, vitest и jest
node docs/media/make-media.mjs      # перерисовать картинки README из настоящих прогонов (нужны ffmpeg и Edge или Chrome)
```

Сборка в `plugin/skills/prove-fix/scripts/` лежит в репозитории: её как есть запускают плагин, skill, CLI и Action. Пересобирайте и коммитьте её при каждом изменении `src/`; CI падает, если они разошлись.
